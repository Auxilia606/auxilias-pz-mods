# Project Zomboid 버전 대응 정책

## 단일 기준

`config/project-zomboid.json`의 `target`이 레포 전체의 목표다.

- `releaseLine`: 모드 배포 트리의 버전 디렉터리와 `versionMin`에 쓰는 값
- `testedBuild`: 실제 로드·플레이 검증을 마친 정확한 게임 빌드

개별 모드가 같은 값을 별도 설정 파일에 반복해서 갖지 않는다. 모드별 문서에는 시험 근거와
예외만 기록한다.

## 버전 변경 순서

1. 새 빌드의 바닐라 스크립트, 이벤트, 아이템·레시피 필드와 모델 규칙의 차이를
   `shared/knowledge`에 기록한다.
2. `releaseLine`을 변경하고 각 모드에 새 버전 디렉터리를 준비한다. 기존 버전 지원을
   유지할지는 명시적으로 결정하며, 검증 없이 디렉터리 이름만 바꾸지 않는다.
3. 각 모드의 루트 및 버전별 `mod.info`를 갱신하고 모드별 정적 검사를 통과시킨다.
4. `./tools/validate.ps1`로 모든 모드를 한 번에 검사한다.
5. 각 모드의 로드·핵심 상호작용·저장 호환 테스트를 실행하고 근거를 모드별
   `docs/SMOKE-TEST.md`에 남긴다.
6. 모든 모드가 같은 정확한 빌드에서 통과한 뒤 `testedBuild`를 갱신한다.

중앙 버전을 먼저 바꾸면 아직 대응하지 않은 모드는 루트 검증에서 실패한다. 이것은 일부
모드만 조용히 오래된 게임 버전에 남는 일을 막기 위한 의도된 릴리스 게이트다.

## 공통 지식의 위치

엔진 동작, 이벤트 시점, 데이터 형식, 버전별 차이처럼 다른 모드에도 적용되는 사실은 이
디렉터리에 기록한다. 밸런스, 아이템 목록, 특정 기능의 설계처럼 한 모드에만 해당하는 내용은
`mods/<slug>/docs`에 둔다. 추측과 실제 검증 결과를 구분하고, 확인한 게임 빌드와 재현 절차를
함께 기록한다.
