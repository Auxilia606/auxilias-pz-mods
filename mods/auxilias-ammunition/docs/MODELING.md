# Ammunition component model pipeline

Five component-only world models are generated by
`source-assets/blender/generate_components.py` with Blender 5.2 LTS:

| Item | Model representation |
|---|---|
| Small Pistol Projectile | One short round-nose projectile without a casing |
| Heavy Pistol Projectile | One wider flat-nose projectile without a casing |
| Rifle Projectile | One long pointed projectile without a casing |
| Shot Charge | A fourteen-pellet metal shot pile without a shotgun hull |
| Shotgun Hull | One red empty hull with a brass base and visible open mouth |

Each projectile and empty hull mesh represents exactly one individually counted item.
Shot Charge is the sole multi-object mesh because one counted charge contains the multiple
pellets required by one shell. None of these items may reuse the vanilla 9mm,
.38 Special, rifle-ammunition, or shotgun-shell meshes because those meshes depict
complete ammunition.

All five FBX files use a single mesh, one material slot, and one UV layer. They share
`media/textures/WorldItems/AuxAmmoComponentAtlas.png`; the model script applies
`scale = 0.01`, matching the repository's Blender-to-Project-Zomboid export convention.
The meshes are authored with X/Y on the ground plane and Z up. A 180-degree X correction
is baked into the game-export copy because Project Zomboid otherwise consumes the FBX Y
and Z axes reversed.

## Regeneration and validation

From the repository root:

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --python 'mods/auxilias-ammunition/source-assets/blender/generate_components.py'
```

The generator writes the reproducible `.blend` source, five FBX files, shared texture,
validation renders, and `work/model-validation/report.json`. It then imports each FBX
again and rejects lost UVs/materials, multiple meshes, changed bounds, or dimensions
outside the intended component ranges.

Repository validation also rejects missing model assets, incomplete model declarations,
wrong item-to-model mappings, and any regression to the four vanilla complete-ammunition
models previously used as placeholders.

Interactive release testing must still place every component on the ground in Build 42.20
and check size, orientation, ground contact, atlas colors, and recognition from the normal
isometric camera.
